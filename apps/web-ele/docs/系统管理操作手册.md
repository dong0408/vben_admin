# Universal Admin · 系统管理操作手册

> 版本：v1.0 · 适用模块：`apps/web-ele` 系统管理（System）适用人群：日常使用本系统的运营、管理员、业务操作人员更新日期：2026-05-06

---

## 一、项目简介

**Universal Admin（web-ele 端）** 是一套基于 Vue 3 + Element Plus + Vben 框架搭建的中后台管理系统。本手册聚焦"**系统管理**"模块，下设三个子菜单：

| 子模块 | 路径 | 主要用途 |
| --- | --- | --- |
| 用户管理 | `系统管理 → 用户管理` | 维护登录账号、分配角色、控制启用/禁用 |
| 角色管理 | `系统管理 → 角色管理` | 创建角色、分配权限、控制角色启用状态 |
| 菜单管理 | `系统管理 → 菜单管理` | 配置左侧导航菜单、按钮权限、外链与内嵌页面 |

进入方式：登录系统后，在左侧导航栏点击 **"系统管理"**，展开二级菜单即可看到三个入口。

---

## 二、登录与进入

1. 打开浏览器，访问公司发放的系统地址。
2. 输入分配给您的 **用户名 / 密码**，点击「登录」。
3. 登录成功后默认跳转到首页（Dashboard）。
4. 在左侧导航栏中找到 **"系统管理"**，点击展开。

> 提示：若您看不到"系统管理"菜单，说明当前账号未被授予管理权限，请联系超级管理员为您分配。

## 三、用户管理

> 路径：系统管理 → 用户管理

### 3.1 页面构成

进入页面后，自上而下分为三块：

1. **搜索区**：用户名、昵称、状态三个筛选条件 + "搜索 / 重置 / 新增用户" 三个按钮。
2. **数据表格**：显示所有用户，列依次为 _用户名、昵称、角色、邮箱、状态、创建时间、操作_。
3. **分页器**：右下角，可切换每页显示 10/20/50/100 条。

### 3.2 查询用户

1. 在搜索区填入条件（可只填一项，也可组合）：
   - **用户名**：模糊匹配，如输入 `adm` 可搜出 `admin`。
   - **昵称**：模糊匹配。
   - **状态**：下拉选择"全部 / 启用 / 禁用"。
2. 点击 **「搜索」** 按钮，表格刷新。
3. 点击 **「重置」** 按钮，清空所有筛选条件并重新加载全量数据。

### 3.3 新增用户

1. 点击右上角 **「新增用户」** 按钮，弹出"新增用户"对话框。
2. 按提示填写：
   - **用户名**（必填）：登录账号，建议使用英文+数字。
   - **昵称**（必填）：在系统内显示的名字。
   - **邮箱**（必填）：用于找回密码、接收通知。
   - **角色**（必填）：从下拉中选择"超级管理员 / 普通用户 / 访客"。
   - **状态**：默认"启用"，禁用后该账号无法登录。
3. 点击 **「确定」** 提交，列表自动刷新并提示"用户创建成功"。
4. 如需放弃，点击 **「取消」** 或弹窗右上角 ✕。

### 3.4 编辑用户

1. 在表格中找到目标行，点击操作列的 **「编辑」**。
2. 弹出"编辑用户"对话框，原信息已自动回填。
3. 修改后点击 **「确定」**，提示"用户更新成功"。

> 注意：用户名通常作为唯一标识，建议谨慎修改。

### 3.5 启用 / 禁用用户

每行操作列右侧有一个 **开关按钮**：

- 开关为绿色（开启）= 启用，用户可正常登录。
- 开关为灰色（关闭）= 禁用，用户登录将被拒绝。

直接点击开关即可切换，系统自动保存并提示结果。

### 3.6 删除用户

1. 点击操作列的 **「删除」**（红色）。
2. 弹出确认提示："确认删除该用户吗？"
3. 点击 **「确定」** 完成删除；点击 **「取消」** 放弃。

> 警告：删除为不可逆操作。如担心误删，建议先"禁用"，确认无人使用后再删除。

### 3.7 批量选择

表格首列为复选框，可单选/多选。后续可结合批量操作按钮（如已开通）使用。

## 四、角色管理

> 路径：系统管理 → 角色管理

角色是"一组权限的集合"。给用户分配角色，比一个个分配权限更简洁。

### 4.1 页面构成

- 顶部卡片标题"角色列表"，右侧 **「新增角色」** 按钮。
- 表格列：_ID、角色名称、角色编码、描述、状态、创建时间、操作_。
- 操作列含 **编辑 / 权限分配 / 删除** 三个按钮。

### 4.2 系统内置角色

系统默认内置如下角色（仅参考，可能根据实际配置不同）：

| 角色名称   | 编码        | 说明               |
| ---------- | ----------- | ------------------ |
| 超级管理员 | SUPER_ADMIN | 拥有全部权限       |
| 系统管理员 | ADMIN       | 用户/角色/菜单管理 |
| 普通用户   | USER        | 基础功能           |
| 访客       | GUEST       | 仅查看公开内容     |
| 审核员     | REVIEWER    | 内容审核           |
| 开发者     | DEVELOPER   | 开发相关功能       |
| 财务专员   | FINANCE     | 财务相关业务       |

### 4.3 新增角色

1. 点击右上角 **「新增角色」**，弹出对话框。
2. 填写：
   - **角色名称**（必填）：中文显示名，如"运营专员"。
   - **角色编码**（必填）：英文唯一标识，建议大写下划线，如 `OPERATION_STAFF`。一旦使用不建议修改。
   - **描述**：简要说明该角色的职责，便于后续识别。
   - **状态**：默认"启用"。
3. 点击 **「确定」** 完成创建。

### 4.4 编辑角色

操作列点击 **「编辑」**，弹窗内修改信息后保存。

### 4.5 权限分配（核心操作）

1. 操作列点击 **「权限分配」**（黄色按钮），弹出"权限分配"窗口。
2. 弹窗中央是一棵 **权限树**，展开后可看到所有菜单与按钮权限。
3. 顶部右侧有 **「全选」** 复选框，可一键勾选/取消所有权限。
4. 在树中按需勾选/取消，父节点会根据子节点自动呈现"半选"状态。
5. 完成后点击右上角 **「保存」**，提示"权限分配成功"。

> 实操建议：
>
> - 新建角色时先分配最小必要权限，再根据反馈逐步增加。
> - 切勿随意修改"超级管理员"权限，避免锁死自己。

### 4.6 启用 / 禁用角色

通过 **编辑** 弹窗内的"状态"切换；禁用后该角色不会再分配新权限给用户登录会话。

### 4.7 删除角色

点击操作列 **「删除」**，确认后删除。

> 警告：若已有用户绑定该角色，删除前请先在"用户管理"中改派他们到其他角色，避免账号失去权限。

## 五、菜单管理

> 路径：系统管理 → 菜单管理

菜单管理用于配置 **左侧导航栏** 显示的菜单结构、按钮级权限点、外链页面等。

### 5.1 页面构成

- 顶部工具条：刷新、列设置、放大显示、**「新增菜单」**。
- 主体为 **树形表格**（父子结构），列：_菜单名称、类型、权限标识、路由地址、组件/链接、状态、操作_。
- 操作列：**新增下级 / 编辑 / 删除**。

### 5.2 五种菜单类型

| 类型             | 用途                                 | 是否在左侧菜单显示 |
| ---------------- | ------------------------------------ | ------------------ |
| 目录（catalog）  | 用作分组的父级，可包含子菜单         | ✅                 |
| 菜单（menu）     | 实际页面入口                         | ✅                 |
| 按钮（button）   | 页面内某操作的权限点（如"导出"按钮） | ❌                 |
| 内嵌（embedded） | 在系统内 iframe 嵌入外部页面         | ✅                 |
| 外链（link）     | 点击后跳转新窗口打开                 | ✅                 |

### 5.3 新增一级菜单

1. 点击工具栏 **「新增菜单」**，右侧滑出抽屉表单。
2. **类型**：选择"目录"或"菜单"。
3. **菜单名称**：英文唯一标识，2~30 字符。
4. **上级菜单**：留空表示顶级。
5. **菜单标题**：左侧导航中显示的中文名。
6. **路由地址**（type=catalog/menu/embedded 必填）：必须以 `/` 开头，如 `/system/user`。
7. **图标**：可在图标选择器中搜索（基于 Carbon 图标集）。
8. **组件**（type=menu 必填）：填入 Vue 组件路径，如 `system/user/index`。
9. **状态**：启用/禁用。
10. 点击 **「保存」**。

### 5.4 新增下级菜单

在父级行的操作列点击 **「新增下级」**，pid 自动绑定。其余字段同上。

### 5.5 新增按钮权限

1. 类型选择 **"按钮"**。
2. **权限标识**（必填）：建议格式 `模块:动作`，如 `user:add`、`order:export`。
3. 上级菜单选定该按钮所属的页面菜单。
4. 保存后，前端代码可通过该权限标识控制按钮显隐。

### 5.6 新增外链 / 内嵌页面

- **外链 link**：填写"链接地址"（合法 URL），点击后浏览器新开标签页。
- **内嵌 embedded**：填写"链接地址"，将以 iframe 形式在系统内打开，左侧菜单仍可使用。

### 5.7 高级设置（可选）

抽屉表单下方"高级设置"提供精细化配置：

| 选项                             | 说明                                 |
| -------------------------------- | ------------------------------------ |
| 缓存路由（keepAlive）            | 切换菜单时保留页面状态，仅 menu 可用 |
| 固定标签（affixTab）             | 顶部标签页固定，不可关闭             |
| 隐藏菜单（hideInMenu）           | 在左侧导航中不展示                   |
| 隐藏子菜单（hideChildrenInMenu） | 父级展示，子级折叠                   |
| 隐藏面包屑                       | 顶部面包屑不展示                     |
| 隐藏标签                         | 不出现在顶部标签页                   |
| 徽标（badge）                    | 在菜单后显示红点或文字提示，如"NEW"  |

### 5.8 编辑 / 删除菜单

- **编辑**：操作列点击「编辑」，抽屉打开后修改保存。
- **删除**：点击「删除」并确认。删除目录会同步影响其下所有子菜单，操作前请确认。

### 5.9 工具栏功能

- **刷新**：重新拉取最新菜单数据。
- **列设置**：选择哪些列显示/隐藏。
- **放大**：表格全屏显示，便于查看。

## 六、典型业务流程示例

### 场景一：为新员工开账号并赋权

1. **角色管理** → 确认是否已有合适角色，没有则新建。
2. **角色管理 → 权限分配** → 给该角色勾选所需菜单/按钮权限并保存。
3. **用户管理 → 新增用户** → 填入员工信息，角色选刚才的角色 → 保存。
4. 通知员工用户名/初始密码，并提醒首次登录修改密码。

### 场景二：临时下线一名员工的访问

- **用户管理** → 找到该员工 → 操作列开关切到"禁用"。
- 复用账号时再切回"启用"即可。

### 场景三：上线一个新页面

1. 开发完成新页面组件（前端代码）。
2. **菜单管理 → 新增菜单**，类型选"菜单"，填入路由地址、组件路径。
3. **角色管理 → 权限分配**，把该新菜单勾给需要看到的角色。
4. 受影响的用户重新登录或刷新即可看到新菜单。

## 七、常见问题（FAQ）

**Q1：登录后看不到"系统管理"菜单？** A：当前账号没有相应权限。请联系拥有"超级管理员"或"系统管理员"角色的同事，在角色权限分配中勾选系统管理相关菜单。

**Q2：新建用户后不能登录？** A：检查 ①状态是否为"启用" ②角色是否分配 ③角色对应的权限是否包含至少一个可访问的菜单。

**Q3：删除/禁用了自己的账号怎么办？** A：使用其他超级管理员账号登录恢复；如全部锁死，需联系系统运维从后端处理。

**Q4：权限分配保存后没生效？** A：受影响用户需要 **重新登录** 或刷新页面才会看到最新权限。

**Q5：菜单图标找不到？** A：图标库使用 Carbon 图标集，可以在 [https://icones.js.org/collection/carbon](https://icones.js.org/collection/carbon) 浏览，复制名称后填入。

**Q6：路由地址填错，菜单点了打不开？** A：路由地址必须以 `/` 开头，且与前端代码中注册的路由一致；组件路径需与 `src/views/` 下文件位置匹配。

## 八、安全与最佳实践

1. **最小权限原则**：每个角色只授予完成本职工作所需的最少权限。
2. **谨慎使用超级管理员**：日常运营建议使用"系统管理员"或自定义角色。
3. **删除前先禁用**：先观察 1~3 天，确认无影响后再删除。
4. **定期审计**：每月检查一次用户列表，禁用离职/转岗员工账号。
5. **角色编码规范**：大写英文 + 下划线，避免后续重命名。
6. **菜单变更告知**：上下线菜单前同步通知相关用户，避免操作中断。

## 九、术语速查

| 术语        | 含义                                   |
| ----------- | -------------------------------------- |
| 用户        | 一个登录账号                           |
| 角色        | 一组权限的集合                         |
| 权限        | 访问某菜单或操作某按钮的资格           |
| 菜单        | 左侧导航中的入口                       |
| 按钮权限    | 页面内某操作（如"导出""删除"）的权限点 |
| 路由        | 页面对应的 URL 路径                    |
| 启用 / 禁用 | 资源是否生效的开关                     |
